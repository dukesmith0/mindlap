How to use this page. Each demo has a [N.N] TITLE identifier you can reference when flagging issues (e.g. "[3.4] looks too small in dark mode"). Toggle theme via the button in the topbar to verify both. Hover, focus, click — every state is live.

This file is a static reference. The Zetamac Pure system shipped via app/globals.css is the source of truth. A standalone HTML file rots — when you change tokens or component styles, update both. The follow-up to fold this into a live /style route inside the Next.js app is filed in .vibe/future.md.

Canonical set (consolidated 2026-05-03): 5 base tokens + --danger + --on-accent + 3 reaction-game tokens; canonical button family (.btn-link, .btn-danger, .btn-sm, .btn-icon, .btn-ghost); styled native checkbox + radio; a single .tag / .tag-accent / .tag-error convention for bracketed status text; .text-muted-sm / .text-muted-xs / .numeric utilities.

[3] buttons

canonical button set (6 variants)

Six canonical button variants. Anything else in the wild is dead code. All hover states are live.

[3.1] primary outlined / button

Default. 1px accent border, accent text → fills accent on hover. The everyday button.

[3.2] btn-link / anchor styled as button

Same look as [3.1] but renders as <a>. Use when the action is real navigation.

play -> sign in

[3.3] btn-danger

Red border + red text → fills danger on hover. Account deletion, decline, remove friend.

[3.4] btn-sm

Small variant. Used by chip-sized actions (today search clear, etc.).

[3.5] btn-icon

Borderless single-glyph button. Used by toast dismiss + today pin.

is-active = pinned/selected state

[3.6] btn-ghost

Large invisible target with line border. Currently .game-tappable. Used for NBack tap-target.

[3.7] disabled state

All variants share the same disabled treatment: --line border, --muted text, not-allowed cursor.

[3.8] focus state (keyboard)

Tab into the button below to see the 1px accent halo. No thicker, no offset.

[5] status / brackets

single canonical bracketed-status convention

Replaces literal [{error}] JSX strings and the deleted BracketPill component. Brackets live in pseudo-elements; do not include them in JSX content.

[5.1] tag muted (.app-tag)

Default. Status + ack messages.

no streak unavailable saved. streak ticked, leaderboard updated. not yet played

[5.2] tag accent (.app-tag-accent)

Bonus / notable status chip (e.g. "2x xp", "new pb").

2x xp new pb bonus

[5.3] tag error (.app-tag-error)

Form validation errors. Per current code, errors use --accent, not --danger. (Open question: should errors be danger? Flag below.)

username is taken passwords don't match

[5.4] tag danger (.app-tag-danger)

Reserved for destructive confirmations / blocking errors. Uses --danger.

this action cannot be undone account deletion is permanent

DECISION NEEDED: Should form errors use [5.3] accent or [5.4] danger? Current code uses accent everywhere; I think danger reads more correctly.

[19] animations

all motion in the app
